Methodology

📐 Token estimates per call

  • Summarisation: ~2,500 in / 400 out
  • Text Simplification: ~800 in / 650 out
  • Knowledge Graph: ~1,000 in / 700 out
  • Socratic Tutor: ~500 in / 350 out
  • Citation Analyser: ~500 in / 400 out
  • Assignment Breakdown: ~400 in / 400 out
  • Study Path: ~400 in / 500 out

👤 Usage tiers (monthly)

  • Light: ~50k tokens — 4 sessions, ~10 calls/session
  • Average: ~200k tokens — 12 sessions, ~15 calls/session
  • Heavy: ~500k tokens — 25 sessions, ~20 calls/session
  • Token split: ~60% input / 40% output

💡 Context

  • Neurodivergent students rely on tool more intensively
  • TTS, reading guide, overlays use zero AI tokens
  • Prompt caching can cut input costs 50–70%
  • Local LLMs have zero marginal cost after setup
  • Prices may change — treat as directional

Summary

Key Takeaways for Grant Applications

💚

Haiku is the mass-deployment model

Under $0.50/student/month for average use — even at 5,000 students that's ~$2,100/month. Viable within Anthropic Academic Credits alone for pilot cohorts.

⚡

Optimal mix adds quality for 67% more cost

$0.70 vs $0.42 delivers Sonnet-level quality on Knowledge Graph and Socratic Tutor — the two features most impactful for deep learning. Worth it for engaged students.

🖥️

Local (Qwen3 8B) matches Haiku on 6 of 8 features

Students with a mid-spec GPU (8GB VRAM) can run at zero marginal cost. Mistral 7B covers 90% of use cases on 4.5GB VRAM. Position local as the NCAD/privacy-first tier.

📉

Prompt caching changes the maths significantly

System prompts and feature schemas are repeated every call. 60% cache hit rate reduces average cost to ~$0.25 (Haiku) or ~$0.45 (optimal mix) — well within grant budgets.

🚫

Opus 4.7 is not viable for free rollout

At $7.80/student/month average, 1,000 students costs $93.6k/year in API fees alone. Reserve Opus for high-stakes institutional premium tiers if ever introduced.

🎯

NLnet €30k covers ~3,500 student-months of optimal mix

Assuming 20% allocated to API costs (€6k), at $0.70/student/month that funds ~714 active students for a year — a credible pilot scale for PATH 4/5 follow-on applications.

LMS Integration — What's Actually Possible

Ordered by student impact — from the barriers learning support and AT teams see every week, to the longer-term possibilities that could transform how neurodivergent students navigate higher education independently.

Tier 1

Better DOM Reading

Content is already on the page — just not extracted. No API keys, no OAuth, no institutional approval needed. These features could be deployed in any higher education institution today, without involving IT.

No IT involvement No API required Works on all LMS setups
💬
Tutor Feedback Reading
Read marked assignment feedback aloud. Learning support staff frequently sit with students doing this manually — because dyslexic students often cannot process dense written critique independently. AssisT would do this automatically, on demand, in the student's own chosen voice and pace.
How it works
Canvas: extract instructor comments from .comment_content and any SpeedGrader annotation text. GC: private comments in the assignment detail view. The TTS engine already handles arbitrary text — this is a targeting problem, not an engine problem. Label speaker: "Instructor comment: …"

High impact
⏱️
Quiz Mode Detection
Automatically switch to a distraction-reduced, focus-first layout the moment a timed quiz opens — no manual activation required. Students already managing anxiety in exam conditions shouldn't need to remember to configure their accessibility tools. The accommodation activates itself.
How it works
Canvas: URL pattern /quizzes/ + presence of .time_running timer element. Moodle: URL pattern mod/quiz/attempt.php. On detection: auto-enable Focus Mode, hide non-reading tools, surface Reading Guide. Parse timer DOM value to drive a pace indicator.
Canvas ✓ Moodle ✓ Google Forms ~
High impact
🧵
Discussion Thread TTS
Read entire discussion threads sequentially, labelled by author. Discussion-based assessment is one of the most common formats in higher education and one of the least accessible for students with reading difficulties. Currently there is no tool that handles this well.
How it works
Canvas: traverse [data-testid="discussion-topic-reply"] nodes in DOM order. Moodle: .forumpost elements. Build an ordered post array with author + body text. Inject prev/next post controls into the AssisT toolbar. TTS reads each post sequentially with author announcement prefix.
Canvas ✓ Moodle ✓ Google Classroom ~
High impact
✅
Submission State Detection
Detect whether a student has already submitted and switch AssisT to "review mode" — foregrounding feedback reading and annotation over brief reading. Context-aware support that mirrors how a learning support tutor would respond differently before and after submission.
How it works
Canvas: check for .submitted or .submission_details elements. GC: detect the "Turned in" status label near the assignment header. Two toolbar states: unsubmitted → reading + breakdown foregrounded; submitted → feedback reader + annotation tools foregrounded.
Canvas ✓ Google Classroom ✓ Moodle ~
Medium impact
📅
Due Date Awareness
Extract assignment due dates and calculate urgency. Show a countdown in the AssisT toolbar and automatically offer task breakdown when a deadline is within 48 hours. Executive function and time management difficulties are among the most common challenges AT teams support.
How it works
Parse due date text from the DOM (Canvas: .assignment-due-date; GC: date element near assignment header). Convert to relative time ("Due in 2 days"). Inject urgency indicator into AssisT toolbar. If delta < 48h and Assignment Breakdown not yet used for this URL → show auto-offer toast.

Tier 2

Smarter Triggering

Behaviour changes that make AssisT proactive rather than reactive. The difference between a tool students have to remember to use and one that recognises the moment they need support and surfaces it — without requiring any action from the student or staff.

Medium effort Client-side only No IT involvement
🔖
Persistent Read State — Resume TTS
Remember where a student left off and offer to resume on return. Students with fatigue, concentration difficulties, or processing differences rarely read content in a single sitting — they return to it multiple times. Removing the cognitive overhead of finding your place makes that viable.
How it works
On TTS pause or page unload: store { url, charOffset, timestamp } in chrome.storage.local. On return: if a saved position exists for this URL, show "Continue from where you left off?" toast. Optional: subtle opacity shift on already-read sections. Cap stored entries at 50 to avoid storage bloat.
Canvas ✓ Google Classroom ✓ Moodle ✓
High impact
📊
Readability Detection (Flesch-Kincaid)
Automatically detect when a brief or reading is too complex and offer to simplify it — before the student struggles and gives up. Most students don't know to ask for simplification. This surfaces the offer the moment they need it, based on the actual text difficulty, not a manual trigger.
How it works
FK formula is ~30 lines of JS, no dependencies, zero AI tokens. Run on extracted text after DOM extraction. Score → reading age: <30 = postgraduate, 30–50 = university, 50–60 = A-level. Display: "This brief is written at university level (reading age 18+) — simplify?" Threshold configurable in Settings → Preferences.
Canvas ✓ Google Classroom ✓ Moodle ✓
High impact
💡
Auto-offer Assignment Breakdown
Offer to break down a new assignment into steps the first time a student opens it — before assignment anxiety sets in. Many students with executive function difficulties never use breakdown tools not because they don't need them, but because they don't think to reach for them at the right moment.
How it works
Store seen-state keyed by assignment URL in chrome.storage.local. On first visit: show a dismissable toast after 3s. Track "dismissed" and "used" separately — don't re-prompt if dismissed, but re-offer if the brief was opened again without using breakdown. Respect a global "don't auto-offer" preference in settings.

High impact
Tier 3

API Integration

Unlocks the most transformative student support scenarios — but requires institutional LMS API access. These are the features that could eventually replace manual interventions currently handled by learning support staff. Worth raising with IT and institutional management as a longer-term direction.

Needs IT involvement OAuth required Institutional approval
📖
Cross-assignment Vocabulary
Build a personal, growing glossary of subject-specific terms across all assignments — automatically. AT staff and learning support tutors currently do this manually with flashcards and glossary sheets. AssisT could automate it and resurface terms with spaced repetition at the right moment, not just when the student thinks to review.
How it works
With API: pull all assignment text → extract noun phrases and specialist terms across briefs. Without API (partial): store every dictionary lookup with timestamp and context in chrome.storage.local. SM-2 spaced-repetition determines when to resurface terms. Display as "Word of the session" on LMS page load.
Canvas ✓ Google Classroom ✓ Moodle ✓
High impact
🗓️
Full Assignment Fetch → Study Plan
Pull all assignments across all enrolled courses and generate a personalised week-by-week study plan. Study planning and workload management are core learning support interventions at most institutions. This would give every student on-demand access to the kind of structured planning support that currently requires a human appointment.
How it works
Canvas: GET /api/v1/courses/{id}/assignments (OAuth scope: url:GET|/api/v1/courses/:course_id/assignments). GC: classroom.googleapis.com/v1/courses/{id}/courseWork. Aggregate titles + due dates + brief text → pass to Study Path Generator AI feature. Requires OAuth token management and storage.
Canvas ✓ Google Classroom ✓ Moodle ~
High impact
🔄
Cross-device Read Progress Sync
Let a student start reading a brief on a college computer and pick up exactly where they left off on their own device at home. Many students with disabilities rely on specific home setups — larger screens, particular voices, quiet environments. Continuity across those contexts removes a real friction point.
How it works
Option A — chrome.storage.sync: 100 KB limit, no server, Chrome account required. Sufficient for position metadata alone. Option B — lightweight sync endpoint: POST/GET progress JSON keyed by hashed identifier. Requires server + privacy policy update. FERPA implications must be reviewed before storing any LMS-derived data server-side.

For AT & Learning Support Teams

Where the Biggest Difference Gets Made

The features most likely to change outcomes for students — in order of how directly they address what learning support staff see every week.

🥇

Tutor feedback reading

Learning support staff sit with students and read feedback aloud more than almost any other single task. This is the one feature that directly automates a high-frequency, high-value human intervention. No other assistive technology tool handles it well.

🥈

Persistent read state

Students with fatigue, concentration difficulties, or processing differences don't read in one sitting — they return again and again. Removing the friction of finding your place is small in engineering terms and large in daily lived experience.

🥉

Readability detection

Most students don't know when they're struggling because the text is too complex — they think they're just not smart enough. A tool that tells them "this is written at postgraduate level" and immediately offers to simplify it reframes the problem and removes the barrier.

4️⃣

Quiz mode detection

Timed exams are the highest-anxiety moment in a student's academic life. An accessibility tool that activates automatically — without requiring a student to remember to configure it under pressure — is a meaningful accommodation that currently has no equivalent.

⛔

Hold on Tier 3 API features

OAuth and institutional approval are real barriers for a free open-source tool. The exception worth pursuing: chrome.storage.sync for cross-device read position needs no server and minimal effort. The vocabulary and study plan features are worth raising with IT as a longer-term institutional conversation.
